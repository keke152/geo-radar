# 项目检查与优化记录（2026-11-11）

本次检查覆盖 FastAPI 接口、SQLite 存储、任务队列、定时计划、网页连接器、桌面启动与前端草稿流程。项目已有较完整的任务状态和防重发设计，修改以可复现的边界问题为主。

## 本次修复

| 问题 | 触发条件与影响 | 修改方向 |
| --- | --- | --- |
| 定时调度异常退出 | 计划处理或读取设置遇到一次异常后，调度协程结束；队列仍活跃，页面可能继续显示正常 | 每轮异常隔离、下轮重试，披露调度错误及存活状态，保留正常取消语义 |
| 提交期间的草稿被清空 | 请求提交后继续修改问题，成功回调无条件清空整个编辑器 | 按已提交快照确认成功，保留期间新增或修改的草稿 |
| 刷新后重复创建任务 | 服务端已经创建批次，客户端没有收到响应；刷新后使用新请求编号再确认 | 在会话草稿中保存请求编号与待确认快照，重试沿用原请求，保留服务端幂等保护 |
| 本机服务信任任意 Host | 外部域名解析到回环地址时，可用该域名构造同源请求，绕过仅检查 Origin 的限制 | 对读写请求均验证本机 Host，并保留原有写请求头和 Origin 检查 |
| 特殊字符破坏 Excel | 回答或导入文字含 XML 1.0 禁止的 U+FFFE、U+FFFF 等字符时，生成无效工作表 XML | 在导出时移除非法字符，保留数据库中的原始回答；消除 XML 节点布尔判断警告 |

修改前的文件保存在项目外层 `.review-backups/2026-11-11/`，可用于逐文件比较和恢复。当前目录没有 Git 仓库，后续建议纳入版本管理；首次提交前应按 `.gitignore` 排除 `.env`、`runtime` 和虚拟环境。

## 后续建议

1. **减少定时刷新时的全量读取。** `/api/bootstrap` 每次读取所有未删除任务，包括完整提示词与回答，再在 Python 中计算统计。前端默认每 6 秒刷新一次。记录增长后，建议将列表、汇总、平台连接状态拆开，使用数据库聚合和按需加载，并针对查询条件建立索引。重构时应保持额度统计包含已删除任务的现有规则。
2. **给每日选题单独设置简短业务主题。** 企业设置允许主营业务最长 500 字，但 `platform_planner.generate_daily` 限制为 50 字。隔离验证中，保存 60 字主营业务后每日整理失败。建议新增独立的每日选题主题，或在启用计划前明确提示长度限制，避免用户只能从后台错误理解原因。
3. **逐步拆分大文件。** `app.py` 集中接口、导入、平台连接和记录管理；`static/app.js` 同时承担设置、连接向导、弹窗和刷新。可按现有业务模块分离路由和界面逻辑，优先保留现有行为，分批迁移测试。
4. **持续维护验证文档。** 本次已为 README 与 `docs/validation.md` 补充当前检查入口，并保留早期验证历史。后续发布时应同步维护当前版本的测试入口与已验证范围。
