# v1.9.4：执行状态与网页采集

## 本次定位

旧版恢复浏览器成功后未及时更新执行阶段，后续新对话或发送控件超时也可能记作 restoring，无法从这些旧日志判断具体停在哪一步。另一个已定位问题是知乎在完成回答后仍可能保留 `/search?q=完整问题` 地址，旧规则只接受数字会话地址，导致有内容却未通过问题绑定。

本机只读诊断还观察到 Kimi、千问的专用窗口处于最小化状态。最小化可能影响网页动作的稳定性等待；这并不证明四条旧记录都由同一原因导致。不能据此把历史“不确定”改为“未发送”或成功。

## 状态与处理

| 阶段 | 展示与处理 |
| --- | --- |
| 明确发生在发送动作之前的准备失败 | 准备未完成；显示具体步骤，检查后人工继续原任务，不自动重试 |
| 已尝试发送，但未取得确认 | 发送结果需核实；先检查原平台会话，不自动重发 |
| 有发送记录，没有完整回答 | 保留已发送状态，重新采集原回答 |
| 取得内容但未绑定完整问题 | 回答待匹配；可以再次采集校验，不重发问题 |
| 问题对应、生成结束与稳定性检查通过 | 已自动校验；只确认采集机制，不核实平台回答中的事实 |

新日志记录发送尝试边界、发送确认、是否可以安全继续及阶段证据版本。恢复成功后先回到准备阶段，触发发送按钮或快捷键之前才记录尝试。界面不再用“窗口已连接”覆盖具体准备错误。

## 窗口与输入保护

通过 Chromium 窗口接口只还原被最小化的本程序专用窗口；普通、最大化和全屏窗口的尺寸及状态不修改。接口不支持时保留原行为并记录诊断，明确还原失败时停止准备。新对话、输入框和发送操作采用有界等待，单次发送不自动重试。

已有未发送草稿会阻止覆盖。恢复阶段允许发送键在空输入时暂不显示，实际填写任务后仍检查控件是否可用。控件扫描得到的归一化选择器只用于本次操作，不改写用户保存配置。

## 知乎绑定

查询形式必须是单个 q 参数，且其规范化值等于完整原始提示词；页面还必须有唯一的非侧栏完整问题和唯一的最终回答。仅关键词匹配、历史栏文本、多个回答、错误或重复参数均不通过。生成结束、非忙碌、稳定性等条件继续保留。

## 验证范围

200项隔离单元及HTTP测试，另有21项知乎离线DOM场景。包含准备失败、点击结果不确定、已确认发送后采集失败、取消及窗口最小化模拟。界面检查使用模拟记录，不发送真实平台问题。

本轮浏览器实站检查被工具停止，因为无法可靠确认专用窗口网址。此后没有继续操作平台窗口或重新发送问题；离线测试不能替代六个平台的真实账号端到端验收。历史异常记录保留原状态和证据。
