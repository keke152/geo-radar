# v2.0.1：平台连接与回答采集

## 豆包有回答，却获取为空

长回答页面采用虚拟消息列表：回答可见时，原问题节点可能暂时不在 DOM 中。旧自动采集必须同时找到完整原问题与其后的回答，因此会拒绝保存；旧手工采集只查消息列表祖先的滚动容器，遗漏了实际位于列表内部的 viewport。

修复后，缺少原问题时会在唯一消息列表内寻找真实滚动容器，有界恢复原问题，仍要求完整提示词和相邻回答可靠对应，然后恢复原滚动位置。不会读取最后一条回答来猜测归属，也不改动输入框或重新发送。“重新获取回答”和自动采集使用相同提取器。诊断只输出结构、计数和匹配布尔值，不输出正文或草稿。

## DeepSeek 的新对话入口能点，却标定失败

部分入口是 React `div`，没有原生按钮标签、按钮角色或可直接读取的 `onclick`。旧识别规则拒绝了这些控件。

新对话专用规则要求完整短标签（如“开启新对话”及其快捷键）、指针样式、可见性和合理按钮尺寸，排除编辑器与普通区域。点击文字、快捷键或嵌套图标归一到同一外层入口。此规则不用于放宽发送按钮识别，标定点击仍会被拦截，不执行原操作。

## 知乎登录报错与频繁验证

`10001：请求参数异常，请升级客户端后重试` 只能确认平台登录请求失败，不能单凭这个错误认定反爬。工作台会识别该登录页错误，并提示本人处理，而不是将它泛化成“输入框不可用”。

减少无效操作的措施：复用已打开的专用登录窗口；保留各平台本机登录资料；连接失败后使用30、60、120秒等退避，最长300秒；识别登录、安全验证或限流提示后停止自动操作，剩余排队任务转为待配置，等待本人处理、检查连接并手动继续。登录页域名仅用于识别与窗口复用，不加入可发送问题的域名。

这些措施不隐藏自动化标识，不修改浏览器指纹，不轮换代理，也不自动完成验证码。平台仍可能要求验证；网页与 API 通道的能力和统计口径不同。
