# v1.9.3：空回答校验与任务弹窗保护

旧版人工保存按钮没有检查回答是否为空，向接口提交空字符串时，会出现“answer String should have at least 1 character”的提示。这是回答字段校验失败，不代表已保存的回答被删除。纯空白也不能作为已核对回答。

## 当前处理

- 尚未取得回答时，人工保存按钮禁用，输入框下说明如何获取或粘贴完整回答。
- 已发送的网页记录可以先使用“自动采集并校验（不重发）”；人工保存需要先粘贴、核对真实回答。
- 空值、缺失、null或纯空白由接口拒绝，并返回明确中文指引；拒绝时不改动原回答、统计依据或核对状态。
- 有效人工回答原样保存，不去掉原文中的换行与首尾空格。人工保存仍表示操作者已核对原平台回答，不验证平台回答事实。
- 保存与采集期间避免重复提交；窗口已关闭或改看另一条记录时，旧请求不能覆盖新窗口的回答或关闭新窗口。

该修复不自动重新发送问题，不伪造未采集到的回答，也不把空回答改成已完成。历史空回答记录仍需从原对话采集或人工补充。

## 验证

新增6项隔离接口测试覆盖空值、纯空白、缺失/null、原文保存、长度限制及任务状态和回收站保护。浏览器夹具覆盖禁用空保存、中文提示、重复点击和弹窗异步响应隔离；测试请求均被模拟，不修改实际回答。
